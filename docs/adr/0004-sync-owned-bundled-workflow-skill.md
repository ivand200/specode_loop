# Sync Workflow Skills into the Target Project

Specode Loop will prefer the host global `do-work` skill when it exists, while still shipping a runner-managed fallback workflow skill in this repository. Because Docker Sandbox only sees the mounted target project, the runner copies host global `do-work` from `$CODEX_HOME/skills/do-work` or `~/.codex/skills/do-work` into `PROJECT_DIR/.agents/skills/do-work` before sandbox execution. The runner copies this skill without modifying the copied files; the sandbox prompt carries the Specode Loop contract for selecting and reporting exactly one eligible AFK phase per sandbox iteration.

The bundled fallback workflow skill directory is named `specode-do-work` and lives under `.agents/skills/specode-do-work` in this repository. Its `SKILL.md` is kept as an exact copy of the global `do-work` skill source of truth and currently declares `name: do-work`. Before each sandbox run, the Python runner copies that directory to `PROJECT_DIR/.agents/skills/specode-do-work` so Docker Sandbox can discover the fallback through the native project-level Codex skill path when the host global `do-work` skill is unavailable.

The runner keeps the required bundled fallback skills in an internal list in `scripts/specode_loop.py`, starting with `specode-do-work`. It does not expose per-skill flags and does not sync unused bundled skills. The sandbox prompt tells Codex to use `do-work` first and fall back to project-local `specode-do-work` if `do-work` is unavailable.

During sync, Specode Loop may overwrite only its owned destination directories, `PROJECT_DIR/.agents/skills/do-work` when a host global `do-work` exists and `PROJECT_DIR/.agents/skills/specode-do-work` for the fallback. It must leave all other target-project `.agents` files and skill directories untouched so the target project can maintain its own repo-level agent configuration alongside runner-managed workflow skills.
